# Filename-authoritative term classes

| | |
|---|---|
| Author | Philip Dye |
| Date | 2026-09-16 |
| Status | accepted 2026-09-16; implemented 2026-09-16 |
| Analyzed against | `4d69d04` |

## Context and scope

A term file is `public` or `private`, and the class decides three behaviors:
whether being tracked is fatal, whether a matched term is printed, and whether
absence is loud. Today the class is declared inside the file, on its first
non-blank line, as `# git-hygiene: public` or `# git-hygiene: private`. A file
declaring nothing is private
([0004](../design/decisions/0004-term-sources-are-layered-classified-and-unioned.md),
[0006](../design/decisions/0006-matched-terms-print-by-source-class.md)).

This proposes that the filename decide the class instead, and that resolved
term files be excluded from scanning. Scope is the classification contract and
the scan input set. The layering, precedence, union merge and negation
authority rules are unchanged, as is the set of locations consulted.

The motivating observation is narrow and mechanical. Every other mechanism that
governs whether a file reaches a commit works on filenames: `.gitignore`
matches names, `git status` and `ls` show names, a reviewer glancing at a
directory reads names. The one property that determines whether a file may be
committed is the one property none of those can see. That is a structural
mismatch rather than a defect to patch, and the reproductions below are what it
costs in practice.

## Evidence

Four reproductions, run against `4d69d04` with the installed console script and
real repositories. Each creates a fresh repository, stages a file, and runs
`check-identifiers --staged`.

**A. A committed team list, written the way anyone would write it.** A tracked
`.deny-terms` holding one term, no directive. Result: exit 1,
`BLOCKED: term resolution failed`, `tracked private term file`. Undeclared
means private, a tracked private file is fatal, and the failure is not specific
to the commit being attempted. Every commit in that repository fails until
someone knows to add a line the file never needed to contain. This is the
primary public use case, and `doc/term-files.md` currently instructs people
into it.

**B. The same list with `# git-hygiene: public` added.** Result: exit 1,
`BLOCKED: staged content matches a denylisted identifier`, `.deny-terms:2`. The
term file is a staged file like any other, so it is scanned against its own
terms and matches. A public list blocks its own commit by existing.

Taken together, A and B mean the public committed list cannot be used. Omitting
the directive bricks the repository; including it makes the file flag itself.

**C. A tracked `.deny-terms.private` at a repository root**, force-added past
any ignore rule. Result: exit 0. Not blocked, and not loaded either. The
repository-root layer probes `.deny-terms` only; the private counterpart is
collected solely by the ancestor walk, which does not include the anchor
directory. So the file is not a term source at all, its terms are silently
unenforced, and because it was never resolved the tracked-private check never
sees it.

**D. A tracked `.deny-terms` declaring `private` in-band.** Result: exit 1,
`tracked private term file`. The intended behavior, and the only one of the
four that is correct.

C is the same failure as A and B seen from the other end. In C the name carries
the right meaning and the resolver ignores it; in A the name carries the right
meaning and the default overrides it. In every case the filename already said
what the file was, and the tool declined to believe it.

## Proposal

**The filename determines the class, and nothing else does.**

| Source | Class |
|---|---|
| `.deny-terms` | public |
| `.deny-terms.private` | private |
| `/etc/git-hygiene/deny-terms` | private |
| `<git dir>/info/deny-terms` | private |
| `$XDG_CONFIG_HOME/git/deny-terms.txt` or `~/.config/git/deny-terms.txt` | private |
| named by `--terms` or `GIT_DENY_TERMS` | by the same name rules; unrecognized names are private |

The first two rows are decided by the file's name. The system, git-dir and
user rows are decided by where the file lives, since those names are fixed
and none of them is a place a committed file can sit.

Private by default survives, but as the treatment of an unrecognized name
rather than as the treatment of a missing line inside a recognized one. A file
called `.deny-terms` is public because of what it is called, so case A cannot
recur.

**The repository-root layer probes `.deny-terms.private` as well.** This closes
C and makes the root behave like every other directory the walk visits.

**A resolved term file is not scanned against its own terms.** A list
containing the terms it denies is the normal case rather than an edge one, and
matching it against itself is never informative. The exclusion is by resolved
path and by source, so it covers only files the resolver actually loaded, and
only their own entries.

Skipping such a file entirely would be wrong. A committed public `.deny-terms`
that picked up a term from someone's private list, by a paste or a merge,
would then publish that term with nothing to stop it, which is the exact leak
this project exists to prevent. So a staged public term file is still scanned
against every other resolved source, private ones included, and a match there
refuses the commit under the usual printing rules: the private term is not
shown unless the caller asks.

**The directive becomes an optional assertion.** `# git-hygiene: public` or
`# git-hygiene: private` may still appear, and it must agree with the name. A
conflict is an error naming the file and both claims, not a precedence
question. This keeps whatever documentation value the line has while removing
its authority, and it gives anyone who has written one a clear signal rather
than a silent reinterpretation.

## What this buys beyond fixing the four cases

The ignore rule can finally agree with the classification. Both speak
filenames, so `.deny-terms.private`, or a broader `*.private` house rule, means
exactly what the resolver means. Under the current model no ignore pattern can
express the in-band case, which is why the protection and the declaration have
never lined up.

The class is knowable without reading the file, which is the order the
decisions actually need: whether a tracked file is fatal should not depend on
parsing the file that is already in the index.

A file cannot contradict itself. There is one source of truth rather than a
name and a line that may disagree and a precedence rule to arbitrate them.

Rewriting a file cannot silently change its class. A generator, a sort, an
editor stripping comments, or a secret written into place by CI all drop the
first line, and case A is what that costs today.

## Alternatives considered

**Keep the directive and make undeclared `.deny-terms` public.** Fixes A alone.
B, C and the ignore-alignment problem all remain, and the class still cannot be
known without reading the file.

**Keep the directive and add a hook refusing any staged `*.private` file.**
This was the original request that led here. It covers C's safety half but not
its functional half: the file is still not loaded, so its terms are still
silently unenforced. It also leaves A and B untouched, and adding a check that
writes its own hook file would recreate the composition problem that
`2026-09-16.multi-check-hooks.md` exists to solve. The check is still worth
having for files the term logic will never look at, and belongs in that
proposal's front end rather than beside it.

**Infer class from location only, dropping `.deny-terms.private` entirely.**
Simpler, but it removes the ability to keep a private list in a shared ancestor
directory, which is a real use and the reason that name exists.

## Compatibility

A personal `~/.config/git/deny-terms.txt`, declared or not, stays private and
keeps working. That is the overwhelmingly common existing case and it is
unaffected.

A file carrying a directive that agrees with its name keeps working. A file
carrying one that disagrees now errors where it previously took precedence
silently, which is the intended change and the only migration anyone has to
make.

Because the public committed list does not currently work at all, as A and B
show, nothing depends on its present behavior. There is no adoption to preserve
there.

This changes the contract 0004 and 0006 rest on, so acceptance means amending
both records rather than adding one that contradicts them.

## Verification

Each reproduction above becomes a test, asserting on the specific message
rather than on the exit code alone, since a crashed run and a refusing run
share an exit code. A is a tracked undeclared `.deny-terms` committing cleanly.
B is the same file not flagging itself. C is a repository-root
`.deny-terms.private` being loaded, enforced, and fatal when tracked. D keeps
its current behavior through the directive-agreement path.

Three further cases have no reproduction yet and need one: a name and a
directive in conflict; an unrecognized name passed through `--terms` being
treated as private; and a staged public `.deny-terms` containing a term that
also appears in a private source. The last must refuse the commit, and the test
plants a known private term and asserts it is absent from both output streams
unless `--show-private-terms` was given.

`--explain` must show the class it derived for every candidate, which is what
makes a misclassification observable rather than something to infer from
behavior.

## Implementation decision log, 2026-09-16

Each entry names the ladder tier that settled it.

**Location rows are private whatever the file is called** (correctness). The
system, user and git-dir candidates carry a fixed class, so a directive of
`public` in `~/.config/git/deny-terms.txt` is a conflict, not a promotion.

**Which contributors a self-scan skips** (correctness). Terms were previously
kept once, under the first source to introduce them. Skipping "the file's own
entries" on that basis would have let a term the team list introduced first,
and a private list named later also held, pass unchecked through the team
list. Each term now records every loaded source that holds it; a term file is
scanned against a term unless the file is its only holder, and a hit is
reported under the first remaining holder's class.

**Negation authorization uses every holder** (correctness). The same
single-provenance model let a public file cancel a term a private file also
held, whenever a public file had introduced it first. That contradicts 0004's
stated rule, so the root was fixed with the rest: a negation must be at least
as strict as every holder.

**`audit-tree` applies the exclusion too** (correctness). Without it, a
repository with a committed team list fails every pre-publish audit, which is
case B again. Under `--objects`, blobs are mapped to term files through
`git log --all --raw` and `git ls-files -s` for that path, and the same rule
applies to each historical version.

**The tracked check passes a forward-slash path** (correctness). The old code
handed `git ls-files` a native path; under a Windows interpreter with Cygwin
git a tracked private list in a subdirectory would not have been recognized.

**Named `.deny-terms` files keep the trust check** (default). The previous
code applied it to any file of that name, not only to walked ones. The
behavior was carried forward rather than dropped silently.

**The missing-source message drops "declared"** (default). It reads
`missing public term source`, since nothing is declared any more.
