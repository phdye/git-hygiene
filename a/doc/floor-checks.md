# Checking the 3.6.8 floor

This project's declared floor is Python 3.6.8, matching RHEL 8.10's shipped
`python3`. Two independent checks are needed to hold it, because neither one
can find what the other finds.

## Why running the tests is not enough

The suite runs under the rhel root's python 3.6.9 and passes. That proves the
code *executes* at the floor. It cannot prove the code is *written* for the
floor, because Python does not evaluate every construct it parses.

The concrete case, found 2026-08-16: `terms.py` annotated a `NamedTuple` field
as `"re.Pattern[str]"`. `re.Pattern` is 3.8+. The annotation is a quoted
string, so it is never evaluated, and 48 tests passed on 3.6.9 with the code
wrong for the floor. Anything that resolved the annotation -
`typing.get_type_hints`, a serializer, an introspecting tool - would fail on a
real RHEL 8.10 box. No amount of additional *running* could have found it.

The mirror-image trap: `typing.Pattern`, the correct 3.6 spelling, was
**removed in 3.12**. A plain import of it would break the modern end of the
supported range. Annotations of this kind belong under `if TYPE_CHECKING:`,
where they never execute and are correct for a checker at either end.

## Check 1: run the suite at the floor

    Remove-Item Env:HOME -EA 0 ; & 'C:\-\rhel\root\bin\bash.exe' -lc \
        'cd /home/phili/repo/git-hygiene ; PYTHONPATH=src python3 -m pytest tests -v'

Expect **50 collected, 48 passed, 2 skipped**. The two skips are
`test_packaging`, and their reason must read:

    needs pre-commit and git >= 2.31 (found git 2.21)

That is the correct and expected skip: `pre-commit` cannot run on git 2.21 at
all, which is the whole reason the native `install-hooks` front end exists.
Confirm the *reason*, not the count - a test that silently stops running looks
exactly like a test that passes.

Note that pytest there is 4.6.11, which predates `pyproject.toml` support, so
`addopts = -m 'not packaging'` is not applied. The packaging tests are
collected rather than deselected and skip via their own `skipif`. Same
outcome, different mechanism; the `skipif` is what keeps the floor run honest.

## Check 2: type-check *targeting* 3.6

    Remove-Item Env:HOME -EA 0 ; & 'C:\-\rhel\root\bin\bash.exe' -lc \
        'cd /home/phili/repo/git-hygiene ; python3 -m mypy --python-version 3.6 \
         --strict --no-incremental --cache-dir=/tmp/m36 \
         src/git_hygiene/__init__.py src/git_hygiene/terms.py \
         src/git_hygiene/resolution.py src/git_hygiene/check_identifiers.py \
         src/git_hygiene/audit_tree.py src/git_hygiene/install_hooks.py'

Expect `Success: no issues found in 6 source files`.

Files are listed explicitly rather than passing `src/git_hygiene`, to exclude
`_version.py`. That file is generated by setuptools_scm, is gitignored, uses
`from __future__ import annotations`, and is not this project's source.

This is a **separate mypy from the one CI runs**, and both are needed:

| | version | targets | finds |
|---|---|---|---|
| dev venv, Windows python | modern | `python_version = "3.10"`, `platform = "linux"` | ordinary type errors, under `--strict` |
| rhel root, python 3.6.9 | 0.971 | `--python-version 3.6` | constructs that do not exist at the floor |

Neither subsumes the other. Modern mypy refuses `python_version` below 3.10
outright, so it structurally cannot perform check 2.

## How mypy 0.971 was installed on the rhel root

Recorded because the path is not obvious and the blocker was a single missing
package. Done 2026-08-16.

- `mypy 0.971` is a pure-Python `py3-none-any` wheel. No compilation.
- `tomli`, `typing_extensions`, `mypy_extensions` likewise.
- `typed_ast 1.5.5` has **no Cygwin wheel** and arrives as an sdist, so it
  must compile. `gcc 7.4.0`, `g++` and `make` were already present.
- The only blocker was missing Python headers. `python36-devel` is in the 2019
  CTM snapshot the rhel root was built from.

Installing it needs `-X`, because the CTM mirror serves no `.sig` files for
archived snapshots and unattended setup otherwise fails with "out of retries":

    Start-Process -FilePath 'C:\-\rhel\setup\setup-x86_64.exe' -ArgumentList \
      '-q','-n','-X','--no-admin','-R','C:\-\rhel\root','-l','C:\-\rhel\setup', \
      '-s','http://ctm.crouchingtigerhiddenfruitbat.org/pub/cygwin/circa/64bit/2019/08/01/131636/', \
      '-P','python36-devel' -Wait -PassThru

Then `python3 -m pip install --user mypy==0.971`. `typed_ast` builds from
sdist against the new headers. Verify with `python3 -m mypy --version`, which
reports `mypy 0.971 (compiled: no)`.

Python itself stays 3.6.9. Do not raise it; matching RHEL 8.10 is the point of
that instance.

## When to run these

Both, before tagging any release, and after any change touching annotations,
`subprocess` calls, or standard-library usage - the three places floor
violations have actually appeared here. Check 2 costs a few seconds and has
already caught one defect that check 1 structurally could not.

CI cannot perform either: GitHub-hosted runners do not offer Python 3.6, and
the floor is not verifiable on a modern interpreter. These are workstation
checks, and that makes them easy to forget, which is why they are written down
rather than remembered.
